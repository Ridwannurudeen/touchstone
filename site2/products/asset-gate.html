Products · AssetGate

The consumer contract

AssetGate is live on X Layer testnet at 0xAac48DC261B04737FDCB101D5049395121034a83, and is not deployed on mainnet. Asked about USTB it returns (false, “status not allowed”) — the latest report is UNVERIFIABLE and this gate admits CONFIRMED only. It is one of the repo's two contracts, written to act on the registry's state, and until it is deployed nothing reads that state in production. This page describes what the contract is written to do — not what anything is doing today.

What it is written to check

Before treating an asset's report as usable, AssetGate is written to require all four of the following, on-chain.

Status

The asset's reported state. An asset published as UNVERIFIABLE is exactly that — the gate is written to refuse it, not to interpret it charitably.

Freshness

Every report carries a valid_until. Sequence 1 expires at 2026-08-18T23:59:59Z; a gate reading an expired report is written to treat the asset as unreported, not as last-known-good.

Publisher lineage

The report names its publisher key id. A gate is written to accept only reports from the publisher lineage it was configured with, so a different signer cannot substitute a friendlier report.

Pinned control-set root

The report commits to the exact control set it was evaluated under. A gate is written to pin that root, so a quietly weakened control set cannot pass as the one that was agreed to.

Written for

Written for, not used by. No protocol consumes Touchstone today, and this page does not claim one does.

Collateral gating

A lending protocol accepting a tokenized fund as collateral can require a current, satisfied report before valuing the asset — and refuse or haircut it when the state is UNVERIFIABLE or the report has expired.

Disclosure monitoring

A risk process can act on registry state instead of polling an issuer's website: sequenced, signed results where an abstention is recorded with the same weight as a pass.

What deployment would take

The registry it reads is live on X Layer testnet at 0x0dAb4A5B7dd24434Ab6564734E26d3d76985352C, chain id 1952, holding three published reports. AssetGate is deployed there and answering. It stays undeployed on mainnet until there is a consumer with a real gating decision to make, and until the approved control set stops moving — requiredControlSetRoot is immutable once set, so pinning a root the project intends to retire would be wrong on the day it was deployed.
