Products · Verifier

Check the work, offline

The bundle is the record; this site is only a rendering of it. Five short Python scripts recompute the signature, the approval-ledger digest, the compilation artifacts, all eight content hashes and both roots — on your machine, with no trust in this page required.

What a bundle contains

The published file is touchstone.verification-bundle.v4. Its sections are the complete input to every check.

signed_report

The report itself with its Ed25519 signature and the key id it was signed under. The canonical bytes travel alongside as report_canonical, so the signature can be checked against exactly what was signed.

approval_ledger

The full text of the approval ledger the report was signed under — every approved control and every declined candidate, with reasons. Its SHA-256 must match the digest inside the signed report.

compilations

The compilation artifacts, keyed by their own SHA-256. Each control points at the artifact it was accepted in; the report's provenance digests must be exactly this set.

control_records

The eight controls in full — subject, cited span, predicate, cadence, approval state. Hashing each record's canonical bytes must reproduce the content hash the report references it by.

evidence_digests

The SHA-256 of each evidence capture the engine retrieved, with source id, role and retrieval time. These chain into the report's evidence root.

published_key

The Ed25519 public key and key id. The report names the same key id as its publisher, so lineage is checkable without any external lookup.

The five checks

Each is a few lines of Python 3. Check 1 needs the cryptography package; the rest are standard library only. The verify page carries the full scripts.

The five offline checks and what each proves
Check What it proves
1 The signature The Ed25519 signature verifies over the canonical report bytes, and those bytes are the same report this site renders.
2 The approval ledger The ledger text in the bundle hashes to the digest the signed report names — the report was signed under exactly this control-set approval history.
3 The compilation artifacts Every artifact hashes to its own key, and the report's provenance digests are exactly those artifacts.
4 The content hashes All eight control records rehash to the content hashes the report references them by. Change one byte of a control and this fails.
5 The roots The control set root and evidence root — domain-separated ordered hash chains — recompute from the bundle alone.

What the checks do not cover

The bundle carries evidence digests, not the evidence artifacts themselves, so these checks cannot replay retrieval or normalization. And no check proves the issuer's figures are true — only that they were published, checked against a cited predicate, and signed. The five limitations carried inside the signed report are reproduced verbatim here.

This site runs no JavaScript, which is enforced at the server with script-src 'none'. Nothing on any page computes an answer for you; every check runs on your machine or not at all.
