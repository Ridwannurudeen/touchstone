The on-chain record

The registry is a contract on X Layer — one on testnet, one on mainnet — that makes each published report permanent. A report lands at a sequence number and stays there; a later report can correct it only by naming it. Five reports have been published, and two of them are corrections that name the report they restate.

How the record behaves

Sequenced, permanent

Reports for an asset are published in sequence. Sequence 1 for USTB is on chain at block 38526525 and will not be edited or replaced.

Corrections by name

A report can name an earlier sequence it corrects via correction_of. The earlier record stays; readers see both, and which one supersedes which. Sequence 1 corrects nothing.

Bound to its control set

Each report carries the digest of the approval ledger it was signed under. Sequence 1 is bound to an eight-control ledger; the five-control set approved later applies only to later sequences.

Readable by contracts

AssetGate is written to gate on this state — status, freshness, publisher lineage, pinned control-set root — but it is live on testnet and not on mainnet, so nothing reads the registry in production today.

Structurally multi-asset, honestly single-operator

The registry is structurally multi-asset and could carry ten assets. The current single-operator design supports two or three daily assets. That ceiling is stated on the coverage page rather than hidden, because publishing the limit is the kind of thing this project says out loud.
